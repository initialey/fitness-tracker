# 60kgログ

70kg → 60kg（筋肉は維持〜増加）のための、毎日開くトレーニング＆食事ログ。
単一 `index.html` の Claude Artifact。公開先: https://claude.ai/artifact/P9AZMVFPrAxYyQVXmfP4C6

このアプリは、同じリポジトリの `artifact/`（コーチの7日サイクル版「トレログ」）とは**別のアプリ**。
データも Artifact も共有していない。

## 公開時の capabilities

```json
{ "db": { "rules": [ { "path": "", "read": "owner", "write": "owner" } ] } }
```

`db` だけ。写真・動画（`assets`）と AI 推定（`sample`）はフェーズ2なので宣言しない。
db が null のとき（ローカルで開いた・権限なし）はメモリ上で動き、「保存されません」と出す。

## データ

固定プラン（曜日ごとの種目・食事の表・サプリ）は **コード側の定数**（`EX` / `DAYS` / `MEALS` / `SUPPS`）。
仕様書で「固定プラン」と決まっているので db には入れない。db に入るのは記録と設定だけ。

`DAYS` のキーは **Day 番号（1〜7）** で、曜日ではない。`EX` は `[名前, 器具, 初期重量kg]`、
セット数とレンジは `DAYS` 側（`[種目id, セット数, 下限, 上限, SS記号]`）。
器具は1段階の刻みを決める: `smith`/`bar` +2.5kg（バー込み）／`db` +2kg（片手）／`stack` ケーブル・マシンの +1枚
（`settings.plateKg`、既定5kg・設定で変えられる）／`bw` 自重。`EX_NOTE` に「片手」「片側」「両手で1個」の注記を持つ。
同じ種目でも曜日でレンジが違うものがあるため（スミスカーフレイズ: 火 3×12-15 / 金 3×10-15）。
自重の種目（懸垂・ハンギングレッグレイズ）は重量欄を出さず「自重」と表示し、回数だけ記録する。
スミスカーフレイズは火・金で同じ id を使うので、前回の重量が日をまたいでつながる。

| コレクション | doc id | 内容 |
|---|---|---|
| `settings` | `main` | startDate（週平均と疲労抜き週の起点）, unit(kg/lb), goalKg(60), riceAdjustG（ご飯の増減 g） |
| `log_workout` | `YYYY-MM-DD` | sets{ "種目id_セット番号": {exerciseId, setNo, weightKg, reps, feel, loggedAt} }（`feel` は `easy`/`ok`/`hard`）、rir{ 種目id: 0〜5 }（旧データ。読むだけ） |
| `log_weight` | `YYYY-MM-DD` | weightKg, bodyFatPct（任意・空可）, loggedAt |
| `log_diet` | `YYYY-MM-DD` | meals{ 食事id: 記録時刻 }, supps{ サプリid: 記録時刻 }, extras[{id, name, kcal, p, f, c, at}]（メニュー外の食事） |

重量は常に kg で保存し、表示だけ lb に換算する（1 lb = 0.45359237 kg）。

## 画面

1. **今日** — Day1〜7 の順にメニューと対象部位（例: Day 1 上半身A【胸・背中】）。種目ごとに「前回 9/30 22.5kg×10,10,10」とセット数×レンジ、
   セットごとに重量×回数を入力。全セットがレンジ上限に届いたら「次回 重量アップ」。
   **種目名をタップするとやり方**が開く（`HOWTO`、全25種目ぶん）。共通の注意（下ろす2秒・上げる1秒、反動なし、
   メイン種目の前に軽い重量で1〜2セット）はトレーニングの見出しの下に1回だけ出す。
   自重の種目は「自重 × 回数」で記録する。食事は「＋ メニュー外の食事を追加」で食品名・kcal・P/F/C（任意）を
   入れると、その日の合計に足される（行は「外」バッジ付きで出て、「消す」で取り消せる）。
   スーパーセット（SS A / SS B）は①②を1枚のカードに破線でつないで出し、「休まず続けて、終わってから休憩」。
   SS でない種目には「休憩 2〜3分」。下に食事6項目＋サプリ3項目のチェックリストと、
   チェック済みの合計 kcal/PFC を目標と並べて出す。
2. **記録** — 毎朝の体重（体脂肪率は任意）。日々の点（欠測日は線をつながない）＋週平均の線＋目標 60kg のライン。
3. **振り返り** — 連続達成日数（トレ／食事／サプリ）、ご飯の調整提案、週平均体重の表、次の疲労抜き週、設定。

## Day の進み方（繰り越し）

曜日ではなく **Day1〜7 の順番**で出す。`replay(upto)` が開始日から1日ずつ読み直して、各日付の Day とサイクルを決める。

- その日に**トレーニングの記録が1つでもあれば**次の Day へ進む。記録がなければそのメニューを翌日に持ち越す
- 予定外に休んだら **「休みの前借り」**: そのサイクルの Day7 を消化済みにしてトレーニング日に変えるので、
  **全体の日程は後ろ倒しにならない**（カーソルが Day7 に来た時点で未記録が1回以上あれば、その日は休みではなく
  次のサイクルの Day1 になる）
- 前借りできる休みがない＝**同じサイクルで2回目の未記録**のときだけ、以降が1日ずつ後ろ倒しになる
- Day7 は曜日に固定されず、カーソルが Day7 に届いた日が休みになる
- **Day7（休み）は記録がなくても**翌日 Day1 へ進み、サイクルが1つ増える
- 今日より先の日付は「順調にこなした場合」の見込みで進めるので、先の予定を見られる
- 繰り越している日は今日画面に「10/3 に記録がなかったので、Day 2 を繰り越しています。このサイクルの休み（Day 7）を
  前借りで消化するので、全体の日程はずれません」（2回目以降は「前借りできる休みがもうないので…」）と1行出す。
  前借りで休みが消えた日には「今日は Day 7（休み）の予定でしたが、休んだ日のぶんを前借りで消化したので Day 1 です」と出す
- `log_*` から毎回読み直すだけの計算で、どの日付にも書き込まない（過去の記録は書き換わらない）

## 休憩タイマー

セットを記入すると自動で始まる。**メイン種目（各 Day の1種目目）は 2分30秒、それ以外は 75秒**。
時間になったら音（WebAudio のビープ）とバイブ（`navigator.vibrate`）で知らせ、次のセットを記入すると数え直す。

- 残り時間はタブの上の固定バーに出し、「次 インクラインスミスプレス 2セット目」も添える。「飛ばす」で閉じられる
- 休憩中かどうかは**最後に記録したセットの `loggedAt` から計算する**ので、アプリを閉じて開き直しても続く
  （終わってから3分以上たった記録では出さない）
- スーパーセットの①を記入したときは休憩を入れず、「休まず ローロウ へ」とだけ出す（②を記入したら 75秒）
- 音は「セットを記入する」というユーザー操作の中で AudioContext を用意しておき、時間になったら鳴らす。
  鳴らせない環境では黙って諦める。振り返りタブの設定で音はオフにできる

## 重量提案（`progression(exId, date)`）

開始日から順に、その種目の記録を1つずつ読んで次回の重量を決める。基準にするのは**実際に挙げた重量**で、
前回の提案値ではない（提案より重く／軽く入れたらそれに追従する）。

| 前回の結果 | 次回 |
|---|---|
| 全セット上限到達＋最終セットが「余裕あり」 | 2段階アップ |
| 全セット上限到達 | 1段階アップ（器具ごとの刻み） |
| レンジ内＋最終セットが「きつい」 | 同じ重量で、同じ回数をもう一度 |
| レンジ内 | 同じ重量で、いちばん少なかった回数 +1 を目標に |
| 下限未満が1回 | 同じ重量でもう一度 |
| 下限未満が2回続いた | −10%（刻みに丸める） |
| セット数が足りない日 | 基準にしない（同じ重量でもう一度） |
| 疲労抜きサイクルの日 | 基準にしない（明けはその前の重量から再開） |
| 記録なし | 初期重量 |

自重種目（懸垂・ディップ・ハンギングレッグレイズ）は重量を上げる代わりに、全セット上限到達で
**回数の上限を15回まで広げる**（「余裕あり」なら2回、それ以外は1回ずつ。15回に届いたら
「これ以上は加重を足す段階」と出す）。

種目カードには「前回 9/27 45kg×8,8,8」「今日の目安 50kg × 6回」＋その理由を1行で出し、
重量欄の薄い数字（placeholder）も提案値にする。

### セットごとの手応えと、その場での次セット提案

重さと回数を入れてセットが記録されると、その行の下に **「どうだった？ 余裕あり / ちょうど / きつい」**
の3つだけが出る（オレンジの文字は未回答のしるし）。選ぶと `sets[種目id_セット番号].feel` に入り、
同じものをもう一度押すと取り消せる。

選んだその場で、次のセットの行に「次は 47.5kg × 6回　余裕があったので1段階重く（+2.5kg）」と出て、
重さ・回数の placeholder もその値になる。

| 直前のセットの手応え | 次のセット |
|---|---|
| 余裕あり（上限未満） | 同じ重さで、上限の回数まで |
| 余裕あり（上限に到達） | 1段階重く、回数は下限から |
| ちょうど | 同じ重さ・同じ回数でもう1セット |
| きつい（下限より上） | 同じ重さで、下限の回数に落とす |
| きつい（下限以下） | 1段階軽く、回数は下限 |
| 自重種目 | 余裕あり +1回／ちょうど 同じ／きつい −1回（レンジの中で） |

手応えは次回の重量決め（上の表）にも使う。旧データの `rir`（0〜5）しか無い日は
3以上を「余裕あり」、0を「きつい」、それ以外を「ちょうど」として読む。

## 集計ルール

- 週平均体重が**2週続けて減らない** → 「ご飯を各食 −30g」を提案（`riceSuggestion()`）
- 週平均体重が**1kg以上減った** → 「ご飯を各食 +30g」を提案
- 提案は「この提案を反映する」で `settings.riceAdjustG` に入り、今日画面のご飯の量と目標 kcal/PFC に反映される
- 体重の週は開始日から7日区切り（Day のサイクルとは別もの）。前週比は**終わった週どうし**で比べる（途中の週は表に「途中」と出すだけ）
- 疲労抜きは **7日サイクルを5回こなすごとに1サイクル**（サイクル 6・12・18…）。そのサイクル中はセット数を
  `Math.ceil(n/2)` にし、通常のセット数も併記する
- 連続達成日数: トレは「Day7 or その日に記録がある」（Day が進む条件と同じ）、食事は6項目すべて、
  サプリは毎日のクレアチン。今日が未達成なら前日から数える（今日でリセットしない）

## 食事の目標

仕様書の表の合計がそのまま目標: **1,815kcal ・ P154 F67 C162**（約1,800kcal）。
ご飯を各食 −30g にすると 1,715kcal ・ P152.6 F66.8 C139.8（炊飯後 100g = 168kcal / P2.5 F0.3 C37.1 で計算）。
