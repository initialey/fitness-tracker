# 60kgログ

70kg → 60kg（筋肉は維持〜増加）のための、毎日開くトレーニング＆食事ログ。
単一 `index.html` の Claude Artifact。公開先: https://claude.ai/artifact/P9AZMVFPrAxYyQVXmfP4C6

このアプリは、同じリポジトリの `artifact/`（コーチの7日サイクル版「トレログ」）とは**別のアプリ**。
データも Artifact も共有していない。

## 公開時の capabilities

```json
{ "db": { "rules": [ { "path": "", "read": "owner", "write": "owner" } ] } }
```

`db` だけ。写真・動画（`assets`）と AI 推定（`sample`）はフェーズ2なので宣言しない。
db が null のとき（ローカルで開いた・権限なし）はメモリ上で動き、「保存されません」と出す。

## データ

固定プラン（曜日ごとの種目・食事の表・サプリ）は **コード側の定数**（`EX` / `DAYS` / `MEALS` / `SUPPS`）。
仕様書で「固定プラン」と決まっているので db には入れない。db に入るのは記録と設定だけ。

| コレクション | doc id | 内容 |
|---|---|---|
| `settings` | `main` | startDate（週平均と疲労抜き週の起点）, unit(kg/lb), goalKg(60), riceAdjustG（ご飯の増減 g） |
| `log_workout` | `YYYY-MM-DD` | sets{ "種目id_セット番号": {exerciseId, setNo, weightKg, reps, loggedAt} } |
| `log_weight` | `YYYY-MM-DD` | weightKg, bodyFatPct（任意・空可）, loggedAt |
| `log_diet` | `YYYY-MM-DD` | meals{ 食事id: 記録時刻 }, supps{ サプリid: 記録時刻 } |

重量は常に kg で保存し、表示だけ lb に換算する（1 lb = 0.45359237 kg）。

## 画面

1. **今日** — 曜日に応じたメニュー。種目ごとに「前回 9/30 22.5kg×10,10,10」とセット数×レンジ、
   セットごとに重量×回数を入力。全セットがレンジ上限に届いたら「次回 重量アップ」。
   スーパーセット（SS A / SS B）は①②を1枚のカードに破線でつないで出し、「休まず続けて、終わってから休憩」。
   SS でない種目には「休憩 2〜3分」。下に食事6項目＋サプリ3項目のチェックリストと、
   チェック済みの合計 kcal/PFC を目標と並べて出す。
2. **記録** — 毎朝の体重（体脂肪率は任意）。日々の点（欠測日は線をつながない）＋週平均の線＋目標 60kg のライン。
3. **振り返り** — 連続達成日数（トレ／食事／サプリ）、ご飯の調整提案、週平均体重の表、次の疲労抜き週、設定。

## 集計ルール

- 週平均体重が**2週続けて減らない** → 「ご飯を各食 −30g」を提案（`riceSuggestion()`）
- 週平均体重が**1kg以上減った** → 「ご飯を各食 +30g」を提案
- 提案は「この提案を反映する」で `settings.riceAdjustG` に入り、今日画面のご飯の量と目標 kcal/PFC に反映される
- 週は開始日から7日区切り。前週比は**終わった週どうし**で比べる（途中の週は表に「途中」と出すだけ）
- 開始日から**5週ごと**（Week 5・10・15…）が疲労抜き週。セット数を `Math.ceil(n/2)` にし、通常のセット数も併記する
- 連続達成日数: トレは「休みの日 or その日の全種目の必須セットが埋まっている」、食事は6項目すべて、
  サプリは毎日のクレアチン。今日が未達成なら前日から数える（今日でリセットしない）

## 食事の目標

仕様書の表の合計がそのまま目標: **1,815kcal ・ P154 F67 C162**（約1,800kcal）。
ご飯を各食 −30g にすると 1,715kcal ・ P152.6 F66.8 C139.8（炊飯後 100g = 168kcal / P2.5 F0.3 C37.1 で計算）。
